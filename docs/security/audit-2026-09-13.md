# Revue de sécurité — 13 septembre 2026

## Périmètre et résultat

Revue locale du code serveur/client, dépendances, variables d’environnement, fichiers exposés, configuration HTTP et préparation GitHub. Il ne s’agit pas d’un test d’intrusion de l’hébergement ou des services externes. Aucun faux prospect envoyé, aucun push ni déploiement.

## Corrections

- Audit npm initial : 9 vulnérabilités signalées, dont une critique. Correctifs compatibles installés ; Next 15.5.25. Surcharge `overrides.next.postcss` vers une version corrigée de la même branche majeure ; résolution effective PostCSS 8.5.28. Audit final : zéro vulnérabilité connue signalée.
- API contact et ROI : validation serveur des types, champs et longueurs, liste blanche des données transmises, consentement explicite pour le ROI, nombres bornés, rejet des tableaux/JSON invalides et des requêtes venant d’une autre origine navigateur.
- Corps des requêtes limité à 32 Kio, limitation de 10 tentatives/minute/IP par processus, mémoire bornée. Les IP sont hachées pour cette mémoire temporaire. Cette limite n’est pas distribuée et dépend d’un proxy fiable.
- Webhooks HTTPS, délai maximum de 10 secondes, réponse publique générique sans détails internes. Les réponses d’erreur ne sont plus assimilées à un succès. Le webhook ROI doit répondre `{"ok":true}` ; vérifier ce contrat avec l’intégration réelle avant ouverture commerciale.
- Le calculateur attend désormais la confirmation avant d’afficher le rapport ; message d’erreur récupérable si échec. Suppression des paramètres et fragments d’URL dans les données transmises.
- Ajout de `nosniff`, anti-framing, politique de référent, permissions navigateur, HSTS et CSP de base (`object-src`, `base-uri`, `frame-ancestors`). Suppression de `X-Powered-By`. Cette CSP n’est pas une protection complète contre l’exécution de scripts injectés.
- Le pixel Meta ne se charge plus avant le choix du visiteur. Refus et acceptation accessibles au même niveau ; réglage réouvrable depuis le footer. Aucun tracking de secours via noscript tant que le composant n’est pas autorisé.
- Gitignore renforcé ; configurations d’agents et secrets exclus. Aucun motif de clé privée, token GitHub, AWS, OpenAI ou Slack trouvé dans les fichiers publiables par le scan ciblé. Les 73 commits accessibles de l’historique ont aussi été examinés par ces motifs sans correspondance. Les valeurs exactes des webhooks locaux ne sont pas présentes dans les assets publics compilés. Ce scan par motifs ne prouve pas l’absence de tout secret.
- Ancien sitemap de sauvegarde retiré de `public/` et conservé dans les archives documentaires. Fichiers AI Studio non utilisés archivés ; briefs historiques regroupés.
- Modèle de workflow GitHub avec permissions lecture seules : installation reproductible, tests sécurité, audit npm, compilation. Conservé dans `docs/ci/quality.yml`, non actif : la connexion GitHub ne dispose pas du droit workflow nécessaire à son installation.

## Vérifications

`npm run test:security` couvre les champs invalides, JSON mal formé, origine étrangère, taille excessive, consentement, valeurs numériques, filtrage des champs, erreur HTTP/webhook, absence de confirmation JSON, indisponibilité et limitation de débit. Fetch est simulé ; aucun appel externe.

`npm run build` : compilation, contrôle des types et génération des 70 entrées réussis. Test visuel local : bandeau lisible, refus persistant après rechargement, aucun script Facebook avant accord, réouverture depuis le footer, aucun débordement à la largeur testée.

## À configurer / limites avant production

- Vérifier les secrets et droits n8n/Apps Script côté hébergeur. Leur configuration, stockage, destinataires, authentification et conservation ne sont pas audités ici.
- Appliquer la limitation anti-abus au pare-feu/proxy partagé. Une protection en mémoire ne couvre ni les instances multiples ni un attaquant distribué. Configurer aussi les délais de lecture HTTP au proxy pour les clients très lents.
- Conserver l’accès éditeur du dépôt restreint : le HTML Markdown du blog est une source de confiance. Ne pas y injecter de contenu utilisateur non relu. Les valeurs des schémas SEO proviennent aussi du dépôt.
- Valider TLS, DNS, restrictions d’accès aux previews et vraies soumissions dans un environnement de test avant publication.
- Les métadonnées de vérification Google/Facebook et identifiants de pixel sont publics par conception ; les URL de webhook restent privées.
- Les brouillons et archives ne sont pas secrets dès lors que le dépôt devient public. Relire leur contenu avant de choisir la visibilité GitHub.
